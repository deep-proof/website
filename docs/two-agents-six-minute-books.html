GPT-6.2 Astra beat GPT-6 Astra on six minute books

A project receives money at one meeting. Months later the minutes say it gave back what it received, without repeating the amount. Across six books written to test that reading problem, GPT-6.2 Astra got every verdict and value right. GPT-6 Astra missed at least one answer in 12 of 24 reviews. Both were plain agents, and their Codex versions differed. The result compares the two setups we ran.

Here is the earlier result as we reported it. On six books of a later edition of the minutes, gpt-6-astra at the xhigh effort setting, working as it does by default, got 169 of 576 answers not right in 24 reviews. A planned extension of this run was not carried out, so we give the count and draw no rate from it.

When we repeated those reviews with the newer agent, 0 of 576 answers were wrong by the same test of verdict and value. Every answer counted, including the control questions within each review. Both agents worked from the command line with a shell, at the same effort setting. Neither had a review skill. These figures describe the plain agents we ran. We did not run our own document-review system in this test.

What went back to the committee?

Imagine reading the minutes to find out how much a project still holds. An early meeting records a payment. Later, the committee hears that the project has given up what it received at that meeting. The second entry can identify the first by the project and the meeting alone. It need not repeat the amount. If you carry the first entry into a ledger and pass over the second, you can add up the ledger correctly and still give the wrong answer.

We wrote the eighth edition to test just that reading problem. These are invented books. From one edition to the next we changed the minutes to make agents miss more answers. For this edition we kept the events and the questions of an earlier design and changed how some returns were recorded. The wording identifies the committee as the original sender and the eventual recipient. The quiet entries leave out the sum, the usual words for paying money back and the name of the officer who handles payments.

We chose those expressions after looking at the searches the older agent had used. Its lists of words rarely picked them up. That gives the comparison a built-in tilt. Both agents faced precisely the same pages, but we had used only the older agent's habits to write them. We can say which one did better here. A comparison on other people's minutes would need evidence of its own.

What the agents did with the pages

After scoring, we read the commands from one session of each agent in full. They were working on the same book and the same report. Both wrote code to sort the paragraphs into kinds of business and kept the ones their rules could not place. The difference showed up when they chose which of those paragraphs to examine.

In the older session, which contained errors, the filter for the paragraphs left over still asked for familiar money words. A quiet return could slip past both the first sort and that second look. In the newer session, the agent inspected leftover paragraphs using broader words, including “committee”. Its code also came to recognise quiet expressions for a return. The word “committee” appeared in searches by both agents. To see the difference in these two sessions, we had to look at which paragraphs each agent searched.

Across the other sessions we have counts of what the commands displayed and what the answers imply about the ledger. The older agent's successful reviews usually displayed nearly all the quiet sentences. In its reviews with mistakes, far fewer appeared. The newer agent's figures accounted for the returns even though most quiet sentences never appeared in full in its output. We infer that examining what the first sort missed helped it. We did not trace that sequence in every review, and some earlier mistakes occurred even when the quiet sentences had been displayed.

What we can say from the comparison

Each book came with two reports. We gave each report to each agent twice, in fresh sessions. One missed payment could spoil several answers in a single report. We therefore counted reviews that contained any answer that was not right. The newer agent had 0 of 24 such reviews. We used a two-sided Fisher exact test on the review counts. We fixed that rule after the first stage was complete and before the remaining reviews began. Its reading was LOWER for the newer agent on these books.

We changed two things between the runs. The older model ran in Codex 0.168.0. The newer model ran in Codex 0.170.0. We never gave the older model these books under the newer program. The difference we measured belongs to the agents as we ran them. We cannot tell how much came from the change of model alone.

There is uncertainty even about another run like this one. With no affected review in the newer run, the upper end of the exact two-sided 95% interval is still about 14.2%. That calculation treats reviews as independent chances to make an error. In practice, four reviews drew on each book. They share the same passages and the same opportunities to overlook a return. A clean set of answers here leaves open what would happen on a fresh book.

Another plain agent, gpt-6.2-sol at xhigh, had 89 of 576 answers not right in 6 of 24 reviews on the same books. We read its three stages separately. We had fixed no test for their sum.
